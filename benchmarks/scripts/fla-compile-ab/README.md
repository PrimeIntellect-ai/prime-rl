# FLA compile A/B

Before/after measurement for compiling the GLM5-next, Qwen3.5 and Qwen3.8 flash next decoder layers through FLA custom ops. Every run uses random-init models truncated to 8 layers, full activation checkpointing, no offloading, cold compile caches and 8 steps on one 8-GPU node.

Setup:
- `stage_models.sh MODELS_DIR` downloads config and tokenizer files only. It lowers Qwen3.8's `ngram_vocab_size_base` to 1M, since the full n-gram table does not fit next to the optimizer on one node; the table sits outside the decoder layers.
- `python make_vlm_data.py DATA_DIR/vlm-synth` writes 64 synthetic image SFT samples for the Qwen VLM runs.

Run each arm with `PYTHON=... MODELS_DIR=... DATA_DIR=... run.sh MODEL ARM SHA`, where MODEL is one of `glm5_next`, `glm5_next_8k`, `qwen3_5`, `qwen3_8_flash_next`. The `glm5_next_cp2`, `qwen3_5_cp2` and `qwen3_8_flash_next_cp2` configs run 20 steps with context parallelism 2 on real variable-length text (the `chat` and `if` splits of `PrimeIntellect/INTELLECT-3-SFT-10K`, staged with `stage_data.sh DATA_DIR`), so each packed row holds several documents and the CP sequence lengths change every step. `glm5_next_cp1`, `qwen3_5_cp1` and `qwen3_8_flash_next_cp1` run the same data without context parallelism. These six configs collect garbage every step, so that Triton autotune garbage does not inflate peak memory. `glm5_next_cp2_fr` runs 50 steps with a 300 s collective timeout; run it with the NCCL flight recorder on (`TORCH_NCCL_TRACE_BUFFER_SIZE`, `TORCH_NCCL_DUMP_ON_TIMEOUT=1`, `TORCH_FR_DUMP_TEMP_FILE`) to check that the ranks issue their collectives in the same order under activation-checkpoint recompute. `HOOK_DIR=frdump` with `FR_DUMP_DIR` set also dumps every rank's flight recorder buffer at exit, for comparing the collective order of a run that did not time out. `HOOK_DIR=stacksample` with `STACK_DIR` set also appends each rank's main-thread Python stack to a file every `STACK_INTERVAL_S` seconds (default 1), to show what a slow step spends its time on. Summarize a run with `python analyze.py OUT_DIR/runs/MODEL-ARM`: compiles and recompile reasons per frame, compile seconds, step-1 time, per-step loss, grad norm and step time. Per-step peak memory per rank is in `OUT_DIR/runs/MODEL-ARM/peaks/rank<R>.jsonl`. For the Qwen3.8 stall study, the runs also set `TRITON_PRINT_AUTOTUNING=1`: `tables.py` summarizes runs against a base, `compile_timeline.py` attributes Dynamo compile seconds to steps, `triton_timeline.py` attributes the Triton binaries written to the run's cache (`CACHE_ROOT/MODEL-ARM/triton`) to steps, `fla_autotune.py` lists each rank's FLA norm autotune keys and seconds, and `numerics.py` prints per-step loss and grad norm differences.

`run.sh` archives each commit from the checkout that holds the harness, or from `REPO` when that is set. `python ab_summary.py OUT_DIR/runs CELL...` compares the `pr1` and `pr2` runs of each cell (a config name such as `qwen3_5_cp2`): step time over all steps and after the last Dynamo compile on any rank, compiles, recompiles with the step and guard behind each, graph breaks, peak memory and the largest loss and grad norm differences. `results/` holds its output for the final A/B.
