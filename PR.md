This PR rewrites DeepSeek V4's mHC write-back backward as one Triton kernel, rewrites the mHC pre-pass backward as a gate kernel and a streams kernel with an opt-in TF32 dot mode, and routes the `hc_head` collapse through DeepGEMM's TF32 prenorm GEMM by zero-padding its 4-row projection to the kernel's row multiple of 8. At 31078 tokens per GPU the pre-pass backward drops from 2.878 to 1.488 ms per call, the write-back backward from 1.148 to 0.952 ms, and the `hc_head` forward from 3.135 to 0.610 ms.

The write-back kernel reads the output gradient, the residual streams and the sublayer output once and writes all four gradients (the old Megatron pair read the `(tokens, 4, hidden)` gradient twice), following DeepSeek's TileKernels design rewritten in Triton, nothing vendored. The pre-pass backward reduces the collapse gradient into gate gradients in a token-blocked pass and writes the input gradient plus the accumulated weight gradient from the same read of the streams in a hidden-slice pass. `PRIME_RL_DSV4_MHC_BWD_PRECISION=tf32` selects round-to-nearest TF32 dots in the backward, which halves the TF32 gradient error versus the MMA's truncation, and the kernels always honor the flag. `PRIME_RL_DSV4_MHC_PAD_PROJECTION=0` restores the multiple-of-8 gate and keeps `hc_head` on the IEEE Triton path. Traces from the campaign's tip profiling run (6 layers, 2 micro batches per step, 4 steps) show the rewrite per micro-batch window: the old pre-backward pair `_bwd_kernel` + `_bwd_weight_kernel` (26 calls, 37.3 ms summed in the main trace) is replaced by `_bwd_gate_kernel` + `_bwd_input_weight_kernel` (26 calls, 18.4 ms), the one-kernel `_post_bda_bwd_kernel` runs the write-back backward (12 calls, median 0.929 ms), and the padded `deep_gemm::sm90_tf32_hc_prenorm_gemm_impl<8u,...>` variant appears alongside the unchanged N=24 layer kernel.

The numbers come from the DSv4 stack A/B campaign on the 6-layer perf proxy (a DeepSeek V4 Flash checkpoint, 262144-token rows, cp 8, ep 8, full activation checkpointing, 20 steps of 8 micro batches, force-balanced routing), run on H200 with FP8 blockwise and on B300 with MXFP8, each paired against its own main arm on the same node. This campaign arm runs with the halo flag off and `PRIME_RL_DSV4_MHC_BWD_PRECISION=tf32` set on both hardware generations. The step-time metric is `time/forward_backward`, the table shows medians over steps 4 to 20, and a negative delta is faster. B300 repeat floors were 0.04 to 0.12 percent.

The arm-minus-main delta is cumulative through the stack: -3.79% on H200 and -4.29% on B300 at 6 layers, with the 43-layer projection at 88.9 versus 93.4 s on H200 and 49.6 versus 51.3 s on B300. Peak memory adds nothing beyond the previous level's footprint. The tf32 backward is the perf lever and the one deliberate numerics trade: with the bf16 gradients FSDP produces it sits at the bf16 output floor (1.67e-3 relative Frobenius against fp64, versus 1.66e-3 for the old IEEE path), and whether it ships is decided by the B300 RL run. The new kernels' IEEE mode has a register-spill regression at the 24-stream shape (19x slower per call), so the level ships with `PRIME_RL_DSV4_MHC_BWD_PRECISION=tf32` as the opt-in and the IEEE fix is a follow-up. The compile bar is clean on both hardware generations (identical Dynamo counts, zero graph breaks, the one-time padded `hc_head` DeepGEMM variant).
