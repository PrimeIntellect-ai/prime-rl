What PR #4565 changes

All changes are in prime-rl; vLLM is unmodified. Two things blocked DSV4: the P/D launch hardcoded DeepEP, which vLLM's MXFP8 MoE kernels cannot run behind, and Mooncake could not register GPU memory on these nodes.

feat(inference)

Per-role P/D settings live in the role engine configs

The all2all backend, the decode CUDA graph mode and prefill_vllm_overrides / decode_vllm_overrides move from a JSON string spliced into two sbatch templates into InferenceConfig.for_pd_role, so they land in inference-{prefill,decode}.json. An explicit inference.vllm.all2all_backend now applies to both roles. With DeepEP, DSV4 decode fails to start (No MXFP8 MoE backends available) and prefill falls back to weight-only Marlin; flashinfer_nvlink_one_sided works when each role fits one node.

fix(inference)

Mooncake registers GPU KV caches through DMA-BUF

Mooncake defaults WITH_NVIDIA_PEERMEM to true and calls plain ibv_reg_mr on GPU memory. Without the nvidia_peermem module every put failed with AddressNotRegistered and the store never held a block. The launch now sets WITH_NVIDIA_PEERMEM=0 on such nodes. The docs add that auto-detected devices include NICs on other fabrics: pin device_name to the GPU fabric.

docs

HiSparse does not support DeepSeek-V4

vLLM rejects HiSparse for DSV4's compressed sparse MLA; the docs say so, because the first error users hit is an unresolved KV cache layout.

Caveats and open items

  • Root cancelled the first set of inference jobs at 12:10 UTC, cutting level 768 at about 70 of 75 minutes. Levels 512 to 128 ran later on resubmitted arms with the same configs; pdmc was not re-run for them, to stay within 4 nodes. Below the thrash point it tracked pd within 0 to 11%.
  • Aggregated episodes often outlast a 75-minute hold, so per-level episode completions understate it.
  • Every arm ran the router with its circuit breaker off, 3 retries and lenient health checks, and the engines with a 3600 s HTTP keep-alive. Under bursts the router's defaults black-hole healthy engines. Not part of the PR.
  • vllm-router 0.2.4 rejects reasoning_effort="max"; the runs pass it as chat_template_kwargs, which the DSV4 template renders identically (verified by prompt token count). RL is unaffected.
  • Mooncake's decode-side save does not extend DSV4 prefix hits: decode stores only part of the five KV groups, so a turn's completion is prefilled again next turn.
  • A role spanning several nodes with MXFP8 would need deepep_v2 (DeepEP v2); the pinned DeepEP wheel is v1.
